# 本轮失败、修复与恢复记录

本轮六次真实训练和30组独立年度核算现已通过。FAILURE_REPORT.md和FAILURE_HANDOFF.json是首次准备阶段停止时的历史快照，不覆盖RESULTS.md与最终HANDOFF.json。

1. 正式入口运行前，固定阈值测试因0.003三项浮点平均略大于0.003，错误预期不提名；修正测试样例，严格提名规则不变。旧代码与诊断保存于implementation_failures/001。
2. 第一次prepare完成全历史X精确重建，在2021标签核验失败：核验错误使用round_trip，而原加载器和官方评分采用默认CSV解析。原默认值逐值一致，解析方式差异最大约9.996e-17。旧代码、已生成部分数据、日志、资源收据保留于implementation_failures/002。
3. 用户明确授权修复并继续，同一目录、同一累计账本，归档第一次部分准备产物。修正仅作用于标签核验解析；预测文件仍以round_trip验收。
4. 恢复启动时，资源门槛检查拒绝；当时没有记录具体失败数值，无法确认原因，不能把后续测量当作失败瞬间证据。子进程和正式fit/predict/评分尚未启动。后来只读复核达到门槛，用户再次明确授权资源重查后继续，所有预算未放宽。
5. 第二次实际prepare通过三个年份的输入核验。首次实际fit前发现恢复前后monotonic起点变化，修正总六小时墙钟为UTC起止差，单阶段/实例仍用该阶段monotonic。原源码封存及前置补充哈希均保留。10项专项测试通过。
6. 实际fit=6、初次predict=6、重载predict=6；无真实fit/predict重试，无失败评分调用。官方/wrapper/独立各30次年度核算通过，月度逻辑360、两实现聚合720。

资源总收据同时包含失败prepare和成功prepare、train、score、audit、finalize；未记录精确时间的前置开发及首次启动拒绝不并入有收据计算耗时。整轮墙钟按首次prepare UTC至最终完成计算，含中途等待授权。峰值仅为0.5秒名义采样的登记进程树RSS，不是瞬时峰值。
